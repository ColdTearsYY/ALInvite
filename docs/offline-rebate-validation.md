# 2.2.1 离线返点验证

验证日期：2026-11-17。构建目标 Java 21；运行时为 Java 25、Lophine/Folia 26.3、真实 LuckPerms 5.5.85。客户端通过 minecraft-protocol 26.1 和 ViaVersion/ViaBackwards 连接，仅监听本地测试端口 35711。

- `mvn -o -q package`：148 项测试，0 失败、0 错误、0 跳过，包含13项新增返点规则/解析测试。
- 真实 LuckPerms 的7组运行验证共42项检查通过，另行验证缺失 LuckPerms 的启动与基础档回退。
- 所有测试使用同一份最终 JAR；JAR 中不含 LuckPerms API、运行探针或测试类。

在线/离线邀请人的 UUID 来自实际客户端连接。邀请关系及月卡权益由隔离探针建立，充值使用测试命令替身；检查了实际数据库订单的返点金额和 PROCESSED 状态、未领取池、返点历史金额之和。未验证生产支付接口、完整 PlayerPoints 命令提供者或代理身份转发。

正常运行检查没有 ERROR、类加载失败或线程归属错误。玩家退出后出现一条实体任务取消警告；缺失 LuckPerms 用例出现预期的基础档回退警告。各隔离进程正常退出0，35711端口释放。

早期未通过的测试保留为历史：首轮单测误用了新建配置、第一轮运行模板人数上限为1、第二轮测试点券替身未注册 points 命令；均调整测试设置后复测。7组/42项检查通过后，无 LuckPerms 测试曾因探针自身引用该API无法加载，随后改为不引用API的最小探针并通过。上述测试问题没有通过修改生产默认配置绕过。

本轮不回算历史返点，不迁移表结构，不改变充值命令本身和领取流程的故障恢复语义。返点订单去重不代表原始点券命令可以安全重复执行。MySQL表仍需InnoDB，离线权限查询使用后端静态上下文，不提供离线世界上下文。

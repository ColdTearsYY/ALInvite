# 玩家菜单（v2.2.3）

使用 `/travel` 打开主菜单。默认菜单为四行，常用功能都有独立左键入口。原命令与兼容别名继续可用。

| 入口 | 信息与操作 |
| --- | --- |
| 邀请额度 | 可用码、预留数、容量、累计在线、已确认规则组、下一发码节点和剩余在线时长；点击刷新 |
| 填写邀请码 / 我的绑定信息 | 未绑定时进入聊天输入；已绑定时显示邀请人姓名并停止重复填写 |
| 我的邀请码 | 每页 28 个可用码；点击后通过聊天卡片复制分享 |
| 我的预邀请 | 新建、查看或取消本人的预邀请，每页 21 条 |
| 奖励处理记录 | 本人最近 100 条处理记录，每页 21 条；显示类型、状态和更新时间 |
| 邀请里程碑 | 查看进度和领取已达成的奖励 |
| 领取充值返利 | 查看累计、待领和当前比例，点击领取；贡献返点按配置权限显示，用于后期兑换 |
| 返利记录 | 查看返利到账和领取记录 |
| 礼包商店 | 查看、购买或切换礼包 |

## 输入和返回

点击「填写邀请码」后，在聊天栏输入邀请码；点击「我的预邀请 → 新建预邀请」后，输入好友游戏名。无需输入命令前缀。游戏名按现有规则校验，为 3–16 位字母、数字或下划线；无效名字会提示重新输入。

默认输入 `Q` 取消，默认 30 秒超时，可通过 `input_dialog.cancel_key` 和 `input_dialog.timeout` 调整。取消或超时返回对应菜单。打开其他菜单会结束原输入，旧回调不会把玩家拉回此前页面。

## 库存和预邀请

查看、刷新、翻页和复制邀请码不会发码、预留或消耗库存。复制前重新检查实际归属及 `AVAILABLE` 状态。库存变化后刷新列表会移除失效条目，并将超出范围的页码调回有效页。

预邀请沿用现有业务校验，创建时占用一枚可用码。默认有效期是 20 个自然小时，离线也计时。列表显示目标、剩余时长和实际到期时间；历史无期限记录显示「无期限」。点击条目进入独立取消确认页，保留则返回列表；确认后按该预约返还原码。重复确认、已变化的预约和不属于本人的预约不能多退或误退。

额度卡片显示累计在线节点，不是现实时间的发码倒计时。默认 `default` 每累计在线 48 小时获得 1 枚码、容量 1；`vip1` 每 24 小时获得 1 枚码、容量 2。可用码和预留码共同占用容量，满库存时跳过节点，不积攒补发资格。尚无已确认规则时显示状态说明，不推测玩家组。

## 奖励和权限

奖励页按当前玩家的实际 UUID 查询，不提供他人记录、内部命令载荷、重试发奖或核销按钮。「已处理」表示工作已确认处理；结果不明的项目显示「等待管理核对」，由管理员使用原有审计流程处理。

预邀请与个人奖励记录要求 `alinvite.use`；绑定、返利、里程碑和礼包继续使用各自的业务校验。贡献返点还需要配置的贡献权限。菜单不会绕过权限、门禁、库存、IP 或已绑定限制。

## 旧菜单和升级

备份 JAR、配置和数据库，停服替换 JAR 后重启。正常升级补齐新的中英文菜单和语言键；本次不更改数据表，也不改变库存发放、绑定或奖励规则。

已有 `main_menu.yml` 的布局和点击动作继续使用。缺少的功能先补到空白槽位或无动作的普通背景，放不下再使用空闲点击方式，并附上操作提示；所有槽位和点击方式均已占用时，日志会提示服主配置。兼容补入只影响渲染，不重写自定义主菜单文件。

新主菜单动作包括 `refresh_main`、`open_codes`、`open_pending`、`open_deliveries`、`open_rebate_history`、`open_veteran` 和 `open_shop`。预邀请页使用 `input_invitee` 新建，`refresh_pending` 刷新；奖励页使用 `refresh_deliveries` 刷新。

## 验证范围

完整构建通过 169 项自动测试。Lophine/Folia 26.3 隔离服通过 120 项检查：真实连接玩家，使用生产监听器模拟点击与聊天，验证页面渲染、原码返还、重复确认、旧回调、分页、权限、本人数据隔离、查询失败和邀请码复制。客户端收到 31 次菜单打开及可复制的分享消息，测试服正常退出，测试端口释放，旧菜单文件保持不变。

本轮运行使用隔离 SQLite，未新增生产 MySQL、代理切服、支付或人工客户端观感验收。该范围与此前版本的数据库和跨服验证分开记录。

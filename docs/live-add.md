# 宽限期内当场邀请

ALInvite 2.2.0 支持邀请人用 `/alinvite add <新人玩家名>` 替已经进入服务器、仍在绑定宽限期内的新人完成邀请。新人无需再输入邀请码；事务成功后解除门禁、恢复游戏模式，并沿用已有的邀请关系、礼包与里程碑发放流程。

## 玩家操作

1. 邀请人已获得入服资格，并有至少一个可用邀请码，可用 `/alinvite code` 或 `/alinvite status` 查询。
2. 新人进入服务器，处于默认 60 秒的绑定宽限期。
3. 邀请人执行 `/alinvite add NewPlayer`。目标名按原有规则使用 3–16 位英文字母、数字或下划线，不区分大小写。
4. 新人收到自动绑定成功提示并解除限制。同服在线的邀请人也会收到已完成绑定提示。

“已预留”表示提交成功，并不代表绑定事务已完成。`/alinvite pending` 可查仍未认领的邀请；成功认领后，该记录消失，邀请统计与奖励记录按原有流程更新。跨服邀请人的即时确认聊天消息不跨服转发，可通过共享统计和待认领记录确认。

## 同服与跨服

同服 `/add` 成功预留后立即触发新人认领检查。另一后端每秒检查当地处于宽限期的在线新人，因此共享 MySQL 时也可当场认领；实际完成时间还包括数据库与服务器调度耗时，不承诺固定一秒内完成。

各后端须运行此版本、共享同一 MySQL 数据库及表前缀，使用一致的账号 UUID 转发，并启用 `binding_gate`。此流程不依赖 Redis。不同数据库之间不互通。

名字用于定位预邀请，最终关系仍绑定新人实际登录所提供的 UUID。插件不会按名字推算正式服 UUID。原生白名单若在登录前拒绝连接，新人尚未进入插件宽限期，需要原有接待服或其他准入安排。

## 边界与库存

- 原始宽限期不会因 `/add`、重复查询或重复提醒重置。数据库事务在截止前受理后可完成；尚未受理的过期或已关闭会话不得消耗邀请码。
- 每次登录各自维护认领状态。离线、会话替换或关闭门禁会撤销该会话尚未执行的认领；旧回调不能清除新会话的限制。
- 邀请人自身仍在门禁内时不能使用 `/add` 邀请他人。本服已经获准进入、未处于绑定宽限期的在线目标，以及共享记录中已经绑定的目标，会被拒绝。
- 重复邀请、多个邀请人争抢、自动认领与手动 `/bind` 竞争，由数据库决定唯一绑定结果；成功绑定只消耗一个码，奖励工作在同一事务中保存。
- 如果自动认领尚未受理新人就离线或超时，预邀请仍按原截止时间保留，可以在有效期内下次登录认领。未使用记录也可用 `/alinvite cancel <玩家名>` 取消。
- 手动绑定其他邀请码抢先成功时，尚未认领的预邀请可能保留至取消或过期；其码仍占预留库存，不会再次绑定或重复发奖。可用 `/alinvite pending` 查看并取消。
- 离线预邀请仍可正常使用。新建记录默认 20 个自然小时有效，离线也计时；取消或过期退回原码一次，成功认领不返还。普通可用邀请码不受该期限影响。

所有原有 IP、邀请次数和准入限制继续生效。数据库暂时故障时保留预留记录；仍处于宽限期时会继续检查，原倒计时保持不变。

## 升级和提示

不新增配置开关。保持 `binding_gate.enabled: true`，并按需使用现有 `binding_gate.grace_period_seconds`。配额继续为 default 累计 48 小时/容量 1，vip1 累计 24 小时/容量 2。

语言资源新增 `commands.add.claimed`，更新 `commands.add.usage`、`no_permission`、`already_joined`、`success`、`auto_bound`、帮助及门禁提醒。现有自定义文本按配置合并机制保留；若仍显示“只支持未登录玩家”，请按新默认文本手动合并这些已有键，无需删除整个配置目录。

验证结果与本次交付的 JAR 校验值见 [在线邀请验证记录](live-add-validation.md)。已有稳定性报告对应扩展前的基线 JAR，本次验证单独记录。
